6.3.6IPA phoneme symbol

One IPA segment per row of phoneme/<stim>_phonemes.csv, giving the same phone as the ARPABET column in the notation most phoneticians and most non-English-speech literature actually read.

App: Sub-word features → PhonemesOutput: phoneme/<stim>_phonemes.csv

6.3.6.1What it is

One IPA segment per row of phoneme/<stim>_phonemes.csv, giving the same phone as the ARPABET column in the notation most phoneticians and most non-English-speech literature actually read. ARPABET EY becomes eɪ; R becomes ɹ; AH with Stress = 0 becomes ə.

This is a relabelling, not a new measurement. IPA and ARPABET carry identical information and are perfectly redundant as regressors — pick one. The column exists so that a collaborator who does not read ARPABET can inspect and share the phoneme CSV, and so phone inventories can be joined against non-ARPABET corpora.

The syllable CSV carries a dash-joined counterpart; see syllable_labels.

⚠️ IPA is not a function of ARPABET alone — it reads Stress too

Two ARPABET vowels correspond to two different IPA vowels depending on the stress digit, so you cannot reconstruct this column from ARPABET by itself, and a lookup table keyed on ARPABET alone will be wrong on the commonest vowel in English:

ARPABET Stress IPA Name
AH 0 ə schwa
AH 1 or 2 ʌ STRUT vowel
ER 0 ɚ unstressed r-coloured vowel
ER 1 or 2 ɝ stressed r-coloured vowel

Both pairs are notational conventions of English IPA practice rather than claims about two acoustically distinct sounds, and both follow directly from how the CMU dictionary encodes stress. ARPABET has no separate symbol for schwa — a reduced vowel is written AH0. This is checkable in the dictionary this pipeline ships and aligns against (data/mfa_data/pretrained_models/dictionary/english_us_arpa.dict):

about    AH0 B AW1 T        # AH0 = /ə/,  AW1 = /aʊ/
sofa     S OW1 F AH0        # final schwa, again AH0
butter   B AH1 T ER0        # AH1 = /ʌ/ (STRUT),  ER0 = /ɚ/
hurt     HH ER1 T           # ER1 = /ɝ/

For ER, the stressed/unstressed split mirrors the standard ⟨ɜ⟩/⟨ə⟩ convention: "in some English adaptations of IPA, ⟨ɝ⟩ and ⟨ɚ⟩ signify stressed and unstressed, respectively, rather than a difference in phonetic quality" (R-coloured vowel).

Every other ARPABET code is stress-independent: EY is eɪ whether it carries 0, 1 or 2.

No stress marks are emitted

IPA transcription normally prefixes a stressed syllable with ˈ (primary) or ˌ (secondary). This column emits neither, for two reasons:

  1. The Stress column already carries that information, in a form you can filter and group on numerically.
  2. ˈ/ˌ are syllable-level diacritics, and this column holds exactly one segment per row. There is no correct place to put them.

If you need conventional IPA output, reassemble it yourself from (IPA, Stress, syllable_id) — the pieces are all present.

6.3.6.5The full table

39 phones, reproduced from sensi/extractors/arpabet_ipa.py, which is the single source of truth. Example words are given with the dominant (highest pronunciation-probability) entry the shipped MFA dictionary lists for them, so every row is independently checkable. english_us_arpa.dict carries a pronunciation-probability weight per entry when a word has more than one — several common words do — and citing a low-probability variant as "the" pronunciation would undercut a page whose whole point is dictionary verification, so the weight is checked for every example below.

K AO1 T is quoted above because it is the entry that actually contains AO; the dominant entry for the word does not. Worth knowing generally: AA and AO are not cleanly separated by this lexicon.

read's dictionary entry is itself a small illustration of the homograph problem discussed in g2p_oov (the same read present/past example MFA's own G2P documentation uses): english_us_arpa.dict carries R IY1 D (present tense, weight 0.87) alongside R EH1 D (past tense, weight 0.99, the dominant entry) and two lower-weight partial forms. R IY1 D is quoted above because it is the entry that illustrates plain R → ɹ, not because it is dominant — a reader who needs "the" pronunciation of read should not assume the present tense without sentence context, which is exactly the ambiguity a spelling-only lookup (dictionary or G2P) cannot resolve on its own.

Three conventions worth naming, because they surprise people:

  • R → ɹ (a lowercase turned r, the alveolar approximant), not r (the alveolar trill). English r is not a trill.
  • G → ɡ is the IPA script g (U+0261), not the ASCII letter g (U+0067). String comparisons against a hand-typed "g" will fail.
  • IY → i and UW → u are bare, without the length mark ː some transcription traditions add.

What is not in the table

spn — MFA's unknown-word phone — and any code outside the 39 above map to the empty string, never to a guess. A wrong IPA symbol entering the data silently is worse than a blank, so arpabet_ipa.to_ipa refuses to approximate. spn rows therefore have empty IPA, empty Stress, and Pron_Source = 'oov_unresolved'; see phoneme.

6.3.6.6In the code

Open in GitHub
  • sensi/extractors/arpabet_ipa.py
  • sensi/extractors/syllabify.py → syllabify_pairs()

Source: sensi/extractors/arpabet_ipa.py — pure lookup, no I/O, no pandas, no third-party dependency.

ARPABET_TO_IPA: dict[str, str]                       # 39 bare codes
def to_ipa(arpabet: str, stress: int | None) -> str  # one segment
def syllable_to_ipa(pairs) -> str                    # dash-joined

ARPABET_TO_IPA lists AH and ER at their stressed values; a small _UNSTRESSED override dict is consulted first when stress == 0. Keeping the stress-dependent rows in a two-entry override rather than expanding the table to 45 stress-qualified keys means the table stays a readable 1:1 phone inventory, and the two exceptions are visible instead of buried.

Three robustness choices, each there to prevent a silent wrong value:

  • A fused label is tolerated. to_ipa("EY2", None) works: the trailing digit is stripped, and the recovered digit is used as the stress, so to_ipa("AH0", None) correctly returns ə. This matters because some callers still hold MFA's raw label.
  • A stress-dependent vowel with stress=None returns the stressed form, never "". This is only a safety default for direct callers of to_ipa: in the pipeline the case never arises, because Stress is always known when IPA is computed.
  • Unknown codes return "". No fallback, no approximation.

syllable_to_ipa drops unmappable segments rather than emitting empty fields, so a syllable containing noise yields d-i, not d--i.

sensi/extractors/syllabify.py:syllabify_pairs is the only production caller. It splits MFA's label once per phone with _split_label and passes the (code, stress) pair to to_ipa for the phoneme row and to syllable_to_ipa for the syllable row — so the two CSVs can never disagree.

Encoding

The .mat and .csv writers emit UTF-8, and pandas.read_csv / scipy.io.loadmat round-trip these symbols unchanged. ⚠️ On Windows, print()ing an IPA character to a cp1252 console raises UnicodeEncodeError; if you need to inspect the column from a terminal, set PYTHONIOENCODING=utf-8 or read the CSV in a notebook. No pipeline code prints IPA, for exactly this reason.

6.3.6.7Library

None. Deliberately: a G2P/IPA library (e.g. phonemizer, eng-to-ipa) would add a dependency, and in some cases a second pronunciation model, to do a 39-row dictionary lookup. Since the input is already ARPABET from MFA, there is nothing to model — only to rename.
