6.3.7Out-of-dictionary words (MFA G2P)

An alignment option, not a feature column: it changes how MFA handles a word that is missing from its pronunciation dictionary.

App: Sub-word features → Out-of-dictionary wordsLibraries: montreal-forced-alignerNot computed in this manual

6.3.7.1What it is

An alignment option, not a feature column: it changes how MFA handles a word that is missing from its pronunciation dictionary. It lives at alignment.g2p_oov in config/features.yaml, on the GUI's Sub-word page ("Out-of-dictionary words"); run.py reads the same setting.

Default: off. Turning it on adds phone identities that were never observed, so nothing gains them unasked.

The problem it addresses

MFA is lexicon-driven: to align a word it must first look the word up in english_us_arpa.dict to know which phones to search the audio for. Words the dictionary has never heard of — unusual proper nouns, coinages, names — have no entry. MFA still aligns them, but against its unknown-word model, whose single phone is spn ("spoken noise"). You get a real interval with no phonetic content: one spn phoneme row, Stress empty, IPA empty, Pron_Source = 'oov_unresolved'.

That is honest but lossy. If a stimulus contains a character named Zorblax, every sub-word analysis simply has a hole where that word was.

What grapheme-to-phoneme (G2P) conversion does

G2P predicts a word's pronunciation from its spelling. Given the letters z-o-r-b-l-a-x, a G2P model trained on the same dictionary's spelling↔pronunciation pairs proposes the phone sequence an English speaker would most plausibly produce: Z AO1 R B L AE2 K S. MFA ships pretrained G2P models per language, and mfa align accepts --g2p_model_path, documented as "Path to G2P model to use for OOV items" (MFA G2P). With the option on, SensiExtractor passes the vendored english_us_arpa G2P model on that flag, so out-of-dictionary words get a generated pronunciation and are aligned with real phone boundaries like any other word.

The affected rows are then marked Pron_Source = 'g2p' — see phoneme.

⚠️ The pronunciation is modeled, not observed

This is the whole reason the option is opt-in. A g2p phone sequence is a hypothesis derived from orthography, not a transcription of what the speaker did. English spelling is an unreliable guide to pronunciation, and proper nouns — exactly the population this option exists for — are the worst case: surnames and place names routinely violate the regularities a G2P model learned.

MFA's own documentation makes essentially the same point, though about a different (adjacent) workflow. On the same mfa g2p dictionary-generating page, the "Per-utterance G2P" section describes a distinct sub-feature — concatenating a top-hypothesis-per-word G2P guess across an entire utterance, with no dictionary produced — and says of it: "This method is largely not recommended as the output is only the top hypothesis per word in isolation as MFA does not have access to necessary higher order information, so homographs may often have the wrong pronunciation (i.e., English present tense read [ɹ iː d] vs English past tense read [ɹ ɛ d]). Use at your own risk." (MFA generate)

That is not a claim about --g2p_model_path (the flag this project uses, which generates one dictionary entry per OOV word for alignment, not a whole-utterance transcript) — the two are related but not the same workflow, and this doc will not pretend otherwise. What carries over honestly is the mechanism the warning is about, not the warning's literal subject: both modes predict a pronunciation from a word's spelling alone, with no access to the sentence it sits in. read is the clean illustration of why that is risky — the same letters are [ɹ iː d] or [ɹ ɛ d] depending on tense, a distinction spelling does not encode and G2P-in- isolation cannot recover. A surname G2P guesses from --g2p_model_path is under the identical constraint: one plausible pronunciation from spelling, no sentence context to disambiguate it — which is exactly why this project treats every g2p phone as a hypothesis rather than ground truth.

The boundaries MFA then finds are real (they come from the acoustic model searching the audio). The identities are not. Practical consequence: g2p rows are fine for onset/duration and phone-count analyses, and questionable for anything that treats the phone label as ground truth. Pron_Source exists so you can partition on this rather than guess.

Verified on a real stimulus: with the option on, Zorblax received Z AO1 R B L AE2 K S, no word was left phone-less, and in-dictionary phones were untouched — diffing the two phone tiers, the only change outside the OOV word was its shared boundary with the following word moving 0.33 → 0.35 s. Every other interval was identical.

⚠️ It does not tell you whether a word was actually spoken

This is the most important thing on the page, because the option's name invites the opposite reading.

MFA is a forced aligner (McAuliffe 2017). It takes the transcript as ground truth and must place every word in it somewhere on the timeline. It has no "this word is absent from the audio" output — not for OOV words, not for any word. A word that appears in the transcript but was never uttered gets squeezed into a sliver of time, stealing it from its neighbours. That limitation is pre-existing and applies to every word in every run, in-dictionary or not; this option neither introduces nor fixes it.

G2P specifically does not adjudicate the question. Verified: because the test audio genuinely says "Bella", the G2P run confidently aligned Z AO1 R B L AE2 K S across the interval where Bella was spoken. G2P recovers pronunciations for unusual words that were spoken; it has no opinion on whether they were.

Detecting genuine transcript/audio mismatch needs per-word alignment likelihood or an ASR cross-check. MFA 3.4.0's align CLI exposes no such output (checked: no likelihood/confidence flag, and no alignment_analysis.csv is produced), so that work is parked as the Correctness scoring roadmap item and is out of scope here.

Turning it on or off re-runs alignment — once

The setting changes MFA's output, so a cached TextGrid produced under the other setting is stale. Alignment persistence handles this: the freshness sidecar written next to each TextGrid records an mfa_g2p key, and its SIDECAR_VERSION was bumped 1 → 2 when the key was added (and to 3 on 2026-10-21 for the one-speaker-per-stimulus layout). So:

  • The first batch run after upgrading re-aligns every stimulus once (the sidecar version changed), then caches normally.
  • Flipping the toggle thereafter re-aligns once and caches again.
  • MFA still runs at most once per document per dispatch — the option changes the arguments, never the number of alignment passes.

Both alignment paths honour the setting. The batch pre-alignment pass (aligner.ensure_alignments) and the per-document path (aligner.align_with_phones with a persist_dir, used when the batch pre-pass failed and fell back) both reuse a TextGrid only when its sidecar matches the current inputs, mfa_g2p included. Before 2026-10-21 the per-document path trusted any existing TextGrid, so flipping this option could silently change nothing there. Only a direct run() call with no output folder (as in some tests) has no persistence directory and runs MFA every time.

6.3.7.2See it

◇ Not computed in this manual

Needs a spoken word that is missing from the pronunciation dictionary; every word in the manual's public-domain recordings is in it, and we do not fabricate audio. With the option on, such a word gets Pron_Source = g2p and modeled phones instead of a single spn.

Columns this feature writes when it runs: ARPABET, Stress, IPA, Pron_Source

6.3.7.5Usage

Turn it on when your stimuli contain unusual proper nouns, invented names or domain jargon and you need sub-word coverage of those words — phoneme/syllable rows, P_Center, phoneme surprisal. Filter on Pron_Source == 'g2p' afterwards to see exactly which words it affected, and spot-check their ARPABET by ear before treating the labels as data.

Leave it off — the default — when you want every phone label in the output to be dictionary-attested. The out-of-dictionary words then appear as single oov_unresolved rows carrying correct timing and no phone identity, which is a clean, self-labelling gap you can exclude in one filter.

Either way you are told which words were affected: any word that ends up with no phonemes at all is reported to stderr and the run log,

[phonemes] WARNING: 2 words had no phonemes (likely OOV): zorblax, mciver

and if you request G2P on a machine whose G2P model is missing, the run warns and proceeds without it rather than failing:

[mfa] WARNING: g2p requested but no G2P model at …; out-of-dictionary
words will align to spn. Run: python scripts/download_models.py

6.3.7.6In the code

Open in GitHub
  • sensi/extractors/aligner.py
  • sensi/extractors/syllabify.py
  • sensi/gui/planner/emit.py
  • sensi/utils/config_yaml.py

Sources: sensi/extractors/aligner.py (the flag, the sidecar, the model path), sensi/extractors/syllabify.py (Pron_Source), scripts/download_models.py (fetching the model).

  • The model. mfa model download g2p english_us_arpa, ~11 MB, into the already-vendored, git-ignored data/mfa_data/pretrained_models/g2p/. scripts/download_models.py fetches it alongside the acoustic model and dictionary, so a fresh checkout that runs the setup script has it. aligner.g2p_model_available() is the existence check.
  • The flag. _run_mfa(corpus_dir, output_dir, *, g2p=False) appends --g2p_model_path <…/english_us_arpa.zip> only when g2p is true and the model file exists; otherwise it warns and runs unchanged.
  • Cache correctness. _freshness_dict includes 'mfa_g2p': bool(g2p) and SIDECAR_VERSION is 2; _is_fresh compares it. g2p is also part of align_with_phones's in-process memo key, so one process cannot serve an alignment cached under the opposite setting. ⚠️ g2p is deliberately keyword-only with default False on align_with_phones, ensure_alignments, _write_sidecar, _is_fresh and _run_mfa. Every pre-existing call site passes its arguments positionally, so making the parameter positional would have broken all of them at once.
  • Plumbing. alignment.g2p_oov (prefs) → sensi/gui/planner/emit.py sets ns.g2p_oov → sensi.pipeline._prealign_batch and sensi.pipeline.run pass it to ensure_alignments / align_with_phones. The GUI and run.py read the same pref. The option is not a per-column toggle and drops no columns — it changes the aligner's behaviour, so it sits in its own alignment prefs section rather than under features. It nonetheless lives in features.yaml rather than run.yaml (sensi/utils/config_yaml.py routes only shared to run.yaml). That is the right home: it is a "what to extract" decision, and it means the GUI's Reset settings turns it back off — the correct behaviour for an opt-in that adds modeled data.
  • Pron_Source derivation is described in phoneme. Briefly: MFA does not mark G2P-derived words in the TextGrid, so provenance is inferred from whether the MFA words-tier form is present in english_us_arpa.dict. Consequence worth knowing: Pron_Source reports g2p on the basis of that dictionary lookup, so a word absent from the dictionary is labelled g2p whenever it came back with real phones. With the option off it cannot have real phones — it can only be spn → oov_unresolved — so the two values do not collide in practice.

6.3.7.7Library

No new dependency. MFA is already required for all alignment; the G2P model is a data asset MFA downloads, and --g2p_model_path is part of mfa align's existing interface.
