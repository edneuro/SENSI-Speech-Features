6.2.1Document-level count columns

Four basic size descriptors per document, all integers, in the document-level summary CSV.

App: Document-level features → CountsOutput: document/documents_summary_<timestamp>.csvLibraries: spaCy

6.2.1.1What it is

Four basic size descriptors per document, all integers, in the document-level summary CSV:

Column Meaning
n_tokens Total token count, including PUNCT.
n_content_tokens Tokens with upos in {NOUN, VERB, ADJ, ADV, PROPN}.
n_sentences Sentence count from spaCy's Doc.sents.
n_paragraphs Paragraph count, from blank-line-separated spans in the raw transcript; a transcript with no blank lines is a single paragraph. See structural_ids.

Every row of the document summary CSV also carries four identifier columns. They have no toggle and are always written:

Column Meaning
stimulus_id The transcript's file stem, original casing (e.g. story1 for story1.txt) — the same id every per-level output filename uses, so the document table joins to them directly.
dictionary_used Semantic-category backend: LIWC if any Sem_LIWC_* column is present, otherwise Empath (also when no semantic columns were produced).
transcript_path Path of the transcript file as the batch found it (keeps the full filename, extension included).
audio_path Path of the paired audio file; empty for text-only items.

6.2.1.4MATLAB

% Load the document-level table (one row per stimulus)
T = readtable('document/documents_summary_<timestamp>.csv', 'TextType', 'string');
T.Properties.VariableNames             % every column in the file
head(T(:, {'stimulus_id', 'n_tokens', 'n_content_tokens', 'n_sentences', 'n_paragraphs'}), 10)                % this feature's columns (first rows)

% Plot
barh(T.n_tokens); yticks(1:height(T)); yticklabels(T.stimulus_id); xlabel('n_tokens')
Run from the output folder. Variable and column names were checked against the real files when this manual was built; the code itself was not run in MATLAB.

6.2.1.5Usage

  • Normalize stimulus-level summaries (mean_* aggregates) — most document-level metrics are sums divided by one of these.
  • Compare stimulus sizes across a corpus: word counts are the basic unit of "how much material is in this stimulus."
  • Filter / weight downstream analyses by content-token count rather than raw token count when controlling for function-word density.

6.2.1.6In the code

Open in GitHub
  • sensi/utils/doc_summary.py → build_doc_summary()
  • sensi/pipeline.py

Derived in sensi/utils/doc_summary.py:build_doc_summary (called from sensi/pipeline.py's document-batch step) from the word-level DataFrame: simple counts over the appropriate row filters (upos in CONTENT_POS = {NOUN, VERB, ADJ, ADV, PROPN} for content tokens, unique sentence_id for sentence count, etc.). PUNCT-aware definitions match the conventions used by Zipf_Freq, Surprisal, and the semantic indicators.
