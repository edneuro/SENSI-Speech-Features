6.1.4Tokens and lemmas

The two most basic lexical columns.

App: Word-level features → Lexical–linguisticOutput: word/<stim>_features.csvLibraries: spaCy

6.1.4.1What it is

The two most basic lexical columns:

Column Meaning
token Surface form of the word as written in the transcript ("running", "banks", ".", "don't"). Includes punctuation as separate rows (flagged by upos == "PUNCT").
lemma Dictionary-form / base form of the token ("running" → "run", "banks" → "bank", "are" → "be"). Useful for collapsing inflectional variants.

6.1.4.4MATLAB

% Load the word-level table (one row per word)
T = readtable('word/lemmas_features.csv', 'TextType', 'string');
T.Properties.VariableNames             % every column in the file
head(T(:, {'token', 'lemma'}), 10)                % this feature's columns (first rows)
Run from the output folder. Variable and column names were checked against the real files when this manual was built; the code itself was not run in MATLAB.

6.1.4.5Usage

  • token is the input to virtually every downstream extractor (frequency lookup, embedding lookup, alignment).
  • lemma is what you join on if you want to aggregate across inflectional forms — e.g. count occurrences of "run" across "runs", "running", "ran".

6.1.4.6In the code

Open in GitHub
  • sensi/extractors/text_parser.py → parse()

Source: sensi/extractors/text_parser.py:parse. Tokens come from spaCy's default tokenizer (rule-based, splits on whitespace + punctuation with a few language-specific exceptions for contractions like "don't" → ["do", "n't"]). Lemmas come from spaCy's en_core_web_sm lemmatizer, which combines a lookup table with rule fallbacks (Honnibal 2020).

6.1.4.7Library

import spacy
nlp = spacy.load("en_core_web_sm")
doc = nlp("The cats were running.")
for tok in doc:
    print(tok.text, tok.lemma_)
# The The
# cats cat
# were be
# running run
# . .
