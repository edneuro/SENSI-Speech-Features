6.4.1Sentence timing

Per-sentence timing and text in the <stim>_sentences.csv sidecar.

App: Sentence features → Sentence timingOutput: sentence/<stim>_sentences.csvLibraries: montreal-forced-aligner, spaCy

6.4.1.1What it is

Per-sentence timing and text in the <stim>_sentences.csv sidecar:

Column Meaning
Onset First word's Onset in the sentence — start of the sentence in audio, in seconds.
End Last word's End in the sentence — end of the sentence in audio, in seconds.
sentence Verbatim sentence text from spaCy (matches the sentence column on the word-level CSV).

Each row joins back to the word-level CSV via sentence_id. Sentences where no word aligned (very rare) → NaN for Onset / End.

6.4.1.2See it

Example LJ003-0007 (LJ Speech, public domain): “Hundreds of women and children came in every morning to spend the day there. And there was no limitation, whatever, to the numbers of visitors admitted to the debtor's side.”
Read from sentence/LJ003-0007_sentences.csv, written by SENSI SpeechFeatures on the example shown here. Nothing on this figure is typed in.

6.4.1.4MATLAB

% Load the sentence-level table (one row per sentence)
T = readtable('sentence/LJ003-0007_sentences.csv', 'TextType', 'string');
T.Properties.VariableNames             % every column in the file
head(T(:, {'sentence_id', 'sentence', 'Onset', 'End'}), 10)                % this feature's columns (first rows)
Run from the output folder. Variable and column names were checked against the real files when this manual was built; the code itself was not run in MATLAB.

6.4.1.5In the code

Open in GitHub
  • sensi/extractors/sentence_prosody.py

Source: sensi/extractors/sentence_prosody.py (the sentence-level extractor that builds the sidecar; despite the name, also handles the timing columns). Implementation derives sentence timing as the min Onset / max End over the words of each sentence — so the sentence interval covers all aligned word audio for that sentence.

sentence is copied from the word-level sentence column (all words in a sentence share the same value, so picking any row works).

6.4.1.6EEG rationale

Sentence-locked analyses look at responses anchored to sentence boundaries — useful for time-locking ERPs / time-frequency analyses to the start (or end) of a syntactic unit. Common use cases:

  • Sentence-onset-locked ERPs / time-frequency analyses, especially for Closure Positive Shift (CPS) and discourse-level effects.
  • Computing sentence-level pitch / volume / HNR summaries — those columns need the sentence timing to slice their windows.
  • Grouping word-level data by sentence for sentence-level aggregates downstream of the SENSI SpeechFeatures outputs.
