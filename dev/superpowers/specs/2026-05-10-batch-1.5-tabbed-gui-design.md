## 1. Background

Batch 1 shipped a folder-pair batch GUI with a single panel: folder pickers, analyzer field, a `Configure categories…` modal, a flat list of feature toggles, and one `Run` button. After using it, the user flagged several design problems:

- The **"Model & dictionary"** section sits alongside **"Features to extract"**, making it look like the LLM model could affect GPT-2 surprisal — it can't. The model belongs *with* LLM-cloze, not in a separate section.
- **Feature toggles** are a flat list; each feature group should have its own visually grouped space with related settings (model, categories) inline.
- **Document-level outputs** currently appear as a sidecar to word-level runs, conflating two analytically distinct workflows. Word-level binary indicators and document-level summaries should be **independent**: independent toggles, independent runs, independent outputs.
- **`Configure categories…`** is shared between word-level and document-level scoring; the user wants these to be configurable separately (you might score 15 categories per word but summarize 50 at the document level).
- **The categories dialog drops the user's unchecks when the window is closed via the X button**, surprising users who expect "close = save" for a settings panel.
- **The categories list looked vague** — most likely because Empath's auto-derived category names are general (`ancient`, `anonymity`, `leadership`); LIWC's names are more domain-specific. (Empath does expose 194 categories, so the list isn't truncated.)
- The user also flagged that the **GUI looks plain and rough**, but explicitly deferred visual polish to a later batch.

This spec defines batch 1.5: a tabbed GUI with independent word-level and document-level workflows, additional doc-level features, and the small bug fixes that surfaced.

## 2. Goals

1. Restructure the GUI into a `ttk.Notebook` with two tabs: **Word level** and **Document level**, each owning its own feature toggles, category selection, model choice, and Run button.
2. Group word-level feature toggles into thematic blocks (Frequency / Semantic / Predictability / Alignment) with related settings (model, categories, dictionary backend) inline with their feature.
3. Ship four doc-level feature groups: counts, aggregates of word-level metrics, lexical diversity (TTR + MTLD), readability (Flesch Reading Ease + FK Grade), category proportions, LIWC summary scores.
4. Emit a single **master doc-level CSV** per batch run (one row per matched pair), replacing the per-stim summary sidecar.
5. Fix the categories dialog so closing via the window X saves the selection (Cancel still discards).
6. Migrate `preferences.json` to a three-section schema: `shared`, `word_level`, `document_level`.
7. Preserve CLI backward compatibility by adding a `--level word|document` flag that defaults to `word`.

## 3. Non-goals (deferred to later batches)

- Visual polish: spacing, typography, color, icons, dark mode. The user has explicitly deferred this — batch 1.5 ships functional reorganization, not redesigned aesthetics.
- Phoneme-level and syllable-level outputs.
- Acoustic prosody (pitch, intensity, voicing) — still batch 2.
- BERT contextual embeddings.
- P-center extraction.
- Caching of word-level outputs to skip recomputation in doc-level runs. Doc-level always recomputes from transcripts in this batch.
- A unified "run both tabs" button. If you want both outputs, run each tab.

## 4. Architecture

### 4.1 Top-level GUI structure

```
+--[ Inputs (shared, always visible) ]---------------------+
| Transcripts folder: [path]              [Browse...]      |
| Audio folder:       [path]              [Browse...]      |
| Output folder:      [path]              [Browse...]      |
| Analyzer name:      [name]                               |
| Dictionary backend: (•) Auto  ( ) LIWC  ( ) Empath       |
|                     (auto-detected: empath)              |
+----------------------------------------------------------+
+--[ Notebook ]--------------------------------------------+
| [ Word level ] [ Document level ]                        |
+----------------------------------------------------------+
| (active tab content)                                     |
+----------------------------------------------------------+
+--[ Status / Log ]----------------------------------------+
| Progress: [############        ]  Status text            |
| Log: scrolltext (read-only)                              |
+----------------------------------------------------------+
```

The **Inputs** section, **status bar**, **log**, and **Cancel button** (in run controls) are shared. The two tabs each own their own feature toggles, settings, and Run button.

### 4.2 Notebook implementation

`gui.py` is reduced to an orchestrator: it builds the shared sections, instantiates a `ttk.Notebook`, and delegates each tab's content to `gui_word_tab.py` and `gui_doc_tab.py`. The shared sections write their state into shared `tk.StringVar` / `tk.BooleanVar` instances that both tabs can read.

```

```

Plus run artifacts (mirrors word-level run):

```

<output_folder>/doc_run_<YYYY-MM-DD_HH-MM-SS>_no-match.csv
```

### 6.4 Execution model

Each pair is processed sequentially. For each pair:

1. Read transcript text.
2. spaCy parse to obtain tokens and content-word filtering (always runs as the prerequisite for many doc-level features).
3. Run only the word-level extractors needed for the selected doc-level features (e.g., if `mean_llm_cloze` is toggled, run `add_llm_cloze`; if `prop_<cat>` is toggled, run `add_semantic_domain`).
4. Aggregate to a one-row summary using `utils.doc_summary.build_doc_summary`.
5. Append the row to the master CSV in memory.
6. After all pairs, write the master CSV to disk.

The doc-level run **does not write per-stim word-level features.csv files**. It only computes the per-word features in memory to derive the doc-level row, then discards.

If a feature requires a word-level extractor that fails (e.g., MFA isn't available), the corresponding doc-level columns are written as NaN for that pair and a warning is recorded in the manifest. The batch does not halt.

## 7. New extractors

### 7.1 `extractors/lexical_diversity.py`

```python
def compute_ttr(tokens: list[str]) -> float
def compute_mtld(tokens: list[str], threshold: float = 0.72) -> float
```

- **TTR**: `len(set(tokens)) / len(tokens)`. Computed on lower-cased content tokens (POS ∈ {NOUN, VERB, ADJ, ADV, PROPN}).
- **MTLD**: walks through content tokens; tracks running TTR; when running TTR drops at-or-below `threshold` (default 0.72 per McCarthy & Jarvis 2010), counts a factor and resets. Final = `len(tokens) / factor_count`. Both forward and reverse passes are computed; the final MTLD is the mean. Partial factor at the end is added as `(1 - running_ttr) / (1 - threshold)`.

Tests use small fixed fixtures with hand-computed expected values.

### 7.2 `extractors/readability.py`

```python
def compute_readability(text: str) -> dict
```

Returns `{'flesch_reading_ease': float, 'flesch_kincaid_grade': float}` using the `textstat` package (added to `requirements.txt` under a `# Readability` comment).

Tests assert: simple text ("The cat ran.") gets high Flesch-RE and low FK-grade; complex text gets the inverse. No exact-value assertions (textstat versions can drift).

### 7.3 `extractors/liwc_summary.py`

```python
def compute_liwc_summary(text: str, dictionary_path: Path) -> dict
```

Returns `{'authentic': float, 'analytic': float, 'tone': float, 'clout': float}`. Uses LIWC's published formulas:

- **Analytic**: weighted combination of article (`article`), preposition (`prep`), pronoun (`pronoun`), verb (`verb`), and several other categories per the LIWC-22 manual.
- **Authentic**: combination of `i`, `pronoun`, `discrep`, etc.
- **Tone**: `posemo - negemo` rescaled to 0–100.
- **Clout**: combination of pronouns, `we`, `you`, etc.

Exact coefficient tables are in the LIWC-22 manual (sections 6.4–6.7). The extractor reads the LIWC dictionary, computes raw category counts on the text, and applies the formulas.

If the active backend is not LIWC, the doc-level run skips this feature group and leaves the columns absent.

### 7.4 Renamed / extended files

- `utils/doc_summary.py` — extended with new feature aggregators and a master-CSV writer.

## 10. CLI changes

New top-level CLI flag:

```
--level word|document    Selects which run to execute in batch mode.
                         Default: word (backward compatible).
```

Existing batch flags (`--transcripts-folder, --audio-folder, --output-folder, --analyzer, --text-extensions, --audio-extensions`) continue to work unchanged.

Existing single-file flags (`--audio, --transcript, --output`) continue to work for one-shot word-level runs. Single-file mode does **not** support `--level document` — doc-level requires batch mode (since the output is a master CSV).

The `--no-edu-freq, --no-sem-domain, --sem-dict, --sem-categories, --no-llm-cloze, --llm-model, --no-surprisal, --no-align, --no-parse` flags continue to work for word-level runs.

New doc-level CLI flags:

```
--no-doc-counts                 Skip n_tokens/n_content_tokens columns
--no-doc-aggregates             Skip mean_<feature> columns
--no-doc-ttr                    Skip TTR
--no-doc-mtld                   Skip MTLD
--no-doc-flesch-ease            Skip Flesch reading ease
--no-doc-fk-grade               Skip Flesch-Kincaid grade
--no-doc-category-proportions   Skip prop_<cat> / count_<cat>
--no-doc-liwc-authentic         Skip Authentic
--no-doc-liwc-analytic          Skip Analytic
--no-doc-liwc-tone              Skip Tone
--no-doc-liwc-clout             Skip Clout
```

The removed `--no-doc-summary` is replaced by these per-feature flags. (Users who want no doc output at all simply don't run `--level document`.)

## Appendix A: Decision log

- 2026-05-10: GUI restructure driven by user feedback after using batch 1. Specific issues: model/dictionary panel confusion, flat feature list, conflated word/doc workflows, categories-X-discards-bug, shared word/doc categories.
- 2026-05-10: Architecture decision = `ttk.Notebook` with two tabs (Word level, Document level). Each tab is fully independent (toggles, model, categories, run button). Shared at top: folder pickers, analyzer, dictionary backend.
- 2026-05-10: Doc-level output shape = one master CSV with one row per stimulus (better for cross-stimulus analyses than the prior per-stim sidecar).
- 2026-05-10: Doc-level data source = always recomputes from transcripts (no caching from word-level CSVs in this batch). Trade-off: simpler implementation, no version-drift risk; cost: redoes expensive work like LLM-cloze when both tabs are run.
- 2026-05-10: Shared backend (LIWC/Empath), independent category selections per tab. Backend lives in the shared inputs section; categories live in each tab's `Configure...` modal.
- 2026-05-10: Categories dialog X-button = save (matches user expectation for settings panels). Cancel button remains as the explicit-discard path.
- 2026-05-10: Doc-level features = counts + aggregates + lexical diversity + readability + category proportions + LIWC summary scores. All independently togglable so users can produce minimal or maximal CSVs as needed.
- 2026-05-10: Lexical diversity = TTR + MTLD (McCarthy & Jarvis 2010). Pure Python, no extra dependencies.
- 2026-05-10: Readability = Flesch Reading Ease + Flesch-Kincaid Grade via the `textstat` package (mature, widely used).
- 2026-05-10: LIWC summary scores = Authentic, Analytic, Tone, Clout per the LIWC-22 manual published formulas. Requires LIWC backend; columns absent when backend is Empath.
- 2026-05-10: CLI `--level` flag defaults to `word` (backward compatible with batch 1's `run_batch`).
- 2026-05-10: Preferences schema split into `shared`, `word_level`, `document_level`. Migration code handles old flat shape for one release.
